# DDR 完整帧三缓冲与动态长度

## 适用版本

本次同时修改 PL、PS、ESP32 和 PC 接收/显示工具，必须配套更新。
PL 控制 ABI 为 `UBF1 / 0x55424631`，SDIO 内部协议为 **3**；
网络仍为 TCP UBST/UBSA v1 或 UDP UBSD v1。旧 bit、旧 PS、旧 ESP32
不能混用，版本不匹配时拒绝上传，不回退到旧 DDR 环形窗口。
未自动烧录、下载、开启扫描/高压，也未生成或覆盖 BOOT.BIN。

## 地址与所有权

| 槽 | 地址 | 容量 |
|---|---|---|
| 0 | 0x20000000 | 1 MiB |
| 1 | 0x20100000 | 1 MiB |
| 2 | 0x20200000 | 1 MiB |

应用链接区域限制在 0x00100000～0x1BFFFFFF，避免应用堆栈触及
USB 的 0x1C000000 缓冲或上述三槽。不会清零、填充 DDR 冒充图像。

槽位依次为 FREE、WRITING、READY、READING。最终 PI 合成输出从逻辑行 0 开始，
必须顺序收到 0～63 行、每行完整结束且点数/抽取档位一致。最后一个 AXI B 响应
成功后才发布 READY。PS 申请租约后才计算 CRC 并发送 SDIO，ESP32 校验完成后
才释放。失败/停止先停止本地 SD1 DMA，确认不再读取才释放；不能证明空闲时保留
租约并停止链路。CPU/JTAG 重启初始化也先限时复位本地 SD1 CMD/DAT，避免继承旧 DMA。

采集不会为慢网络无限等待。优先空槽，再回收最旧的未占用 READY；
绝不覆盖 READING。已读取后释放的 READY 保留供停扫重传，回收它不计丢帧。
未读取旧帧被淘汰、无槽或错误帧才计源端丢弃。配置事务先停止扫描并确认处理、
FIFO 与 AXI 已排空；确认失败不下发配置。修改配置使旧格式的未占用帧失效。

连续上传使用帧号水位，不重复发送最后一帧；停扫后连续模式等待新帧。
单帧可重传最后完整帧，无完整帧时最多等待 30 秒。上传不负责启动扫描或高压。
USB 参数配置保留；USB 图像已恢复为受保护完整帧读取，但仅支持不抽取、787456 字节，
默认仍选 SDIO/Wi-Fi，详见 [USB 完整帧说明](USB_FRAME_TRANSFER.md)。USB 不回退到旧环形窗口。

## 线头与动态长度

原有每线 8 个 16 位字原样保留，第 5、6 字不占用。原始点数固定 6144，
现有 RTL 的首字保持 0x1C00，第二字 0x1800；第三字低 7 位为线号，
第四字低 4 位为抽取配置，第 7、8 字为原始时间戳。
不要将传输长度反写入线头第二字。

| T_timing_hex[9] | 抽取倍率 | 输出点/线 | 每帧字节 | 有效采样率 |
|---|---:|---:|---:|---:|
| 0 | 1 | 6144 | 787456 | 25 MHz |
| 1 | 2 | 3072 | 394240 | 12.5 MHz |
| 2 | 4 | 1536 | 197632 | 6.25 MHz |
| 3 | 8 | 768 | 99328 | 3.125 MHz |
| 4 | 16 | 384 | 50176 | 1.5625 MHz |

其他档位及非 6144 原始点数拒绝。每帧为 64 × (8 + 输出点数) × 2，
每档末尾均有 1024 字节短 AXI 突发，SDIO 最后窗口均为两个 512 字节块。
ESP32 仍只分配两个最大帧 PSRAM 槽位，实际接收/CRC/提交使用包头长度。
PC 默认按网络头动态接收；显式 `--length` 仍是严格长度限制。
显示端必须逐完整载荷验证 64 行，不跨载荷拼线；抽取后按原始深度位置取 TGC，
按表中有效采样率扫描转换，抽取改变时清除平滑参考。

## 简短 PC 命令

在 esp32c61 目录，接收一帧并保存为每行一个 16 位十六进制字的 TXT：

```powershell
python .\pc_tools\sdio_tcp_receiver.py --port 50001 --source-ip 192.168.3.27 --frames 1 --idle-timeout 120 --output-dir .\image_capture --log image_dynamic.jsonl
```

先启动监听，再点击 ESP32 页“SDIO 单帧”。原始 PSRAM 自测继续用原始 UDP 工具。
真实成像数据不要加 `--test-pattern`。切换为 UDP 编译时使用 sdio_udp_receiver.py。

实时显示：

```powershell
python .\pc_tools\bmode_web_viewer.py --device-ip 192.168.3.27
```

浏览器打开 http://127.0.0.1:8080/，点击“开始接收”即可。图像页仍不控制扫描/高压。
连续吞吐记录（不自动改变采集状态）：

```powershell
python .\pc_tools\sdio_benchmark.py --device-ip 192.168.3.27 --seconds 60 --log image_dynamic_60s.jsonl
```

## PL 控制寄存器

BRAM 物理基址 0x40000000，窗口偏移 0x004C0200；下表偏移相对窗口。
全字 32 位读写；参数 BRAM 与 AXI 写入器同属 clk_100m，不增加多位 CDC。

| 偏移 | 功能 |
|---|---|
| 0x00 | 只读 ABI 0x55424631 |
| 0x04 / 0x08 | 命令 / 最后写入提交序号 |
| 0x0C / 0x10 | 确认序号 / 结果：0成功、1无新帧、2忙、3无效 |
| 0x14 | bit0初始化、bit1帧写入/AXI忙、bit2处理忙、bit3配置暂停 |
| 0x18～0x28 | 稳定快照：槽号、帧号、有效字节、抽取档、租约 |
| 0x2C / 0x30 | 申请水位（0允许最后帧）/ 释放租约 |
| 0x34 / 0x38 | 源端淘汰/丢弃 / 错误累计 |
| 0x3C / 0x40 / 0x44 | 每槽2位状态 / 最新完整帧 / 成功发布累计 |

命令 1 INIT、2 ACQUIRE、3 RELEASE、4 PAUSE、5 RESUME。
先写参数、命令，再写新序号；等待匹配 ACK 才读快照。
INIT/PAUSE 等待实际处理和 AXI 排空，并通过跨域请求—确认清理 FIFO。
租约递增，迟到释放无效；INIT 只能由已确认本地 DMA 停止的新主机调用。

## 验证与板测边界

RTL 自检查使用真实 XPM 异步 FIFO，不用假 FIFO 替代 CDC。
新增单 bit 同步器仅第一同步级 D 引脚设置局部例外，XPM 提供 Gray 指针约束。
原有 AFE/系统整时钟组例外会覆盖 XPM 的 max-delay，因此改为仅穿过旧模块
端点的局部例外，明确排除新增帧缓存及处理忙同步器；这些旧路径仍是既有
CDC 技术债，不能据此宣称全设计 CDC clean。AFE/MMCM 和 ila_bf 原探针不改。

构建、测试结果及产物绝对路径/哈希见 [验证记录](DDR_FRAME_STORE_VALIDATION.md)；仿真不等于板级验收。
重新下载/烧录及 BOOT 打包须另行确认。板测应分别记录：

1. 五档采集中完整帧字节/CRC/64行一致，确认采集中无覆盖导致的 CRC 错误。
2. 停扫后两次单帧内容相同；连续模式不重放同一帧。
3. 限速 PC，观察源端淘汰但不覆盖租约，不积压延迟。
4. 两端独立重启、断网、取消、配置档位切换，确认无旧帧串入新会话。
5. 记录 PL 发布帧率、SDIO 接收耗时、PC 有效帧率/吞吐、显示帧率、
   各段错误/丢弃及堆低水位；连续运行 48 小时。

温度相关 AFE 时钟故障独立待查，不视为本次 DDR 修复已解决。
