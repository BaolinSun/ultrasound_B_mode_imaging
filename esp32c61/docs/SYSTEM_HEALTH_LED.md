# 系统健康指示灯 LED_1

`LED_1_EMIO_PIN` 改为系统关键功能就绪指示，不再跟随高压使能。上电初始化阶段输出 0；全部检查通过才输出 1。

## 亮灯条件

| 检查项 | 条件 |
|---|---|
| 启动 | 主应用初始化流程结束，冷启动温度恢复不再阻止工作 |
| DDR | 帧槽位接口 ABI、初始化状态正常，PL 帧缓存错误计数为 0 |
| AFE | READY、真实时钟/MMCM/对齐及恢复代次检查通过，最近 AFE SPI 操作成功 |
| TX | READY、当前硬件控制确认正常 |
| SDIO/Wi-Fi 模式 | PS 与 ESP32 握手正常，ESP32 Wi-Fi 已连接、目标 IP 已配置、发送服务无 TCP 失败；500 ms 心跳持续推进，健康快照不过期；在途传输连续 2 秒无进度时不亮 |
| USB 图像模式 | USB 传输层已初始化、主机已配置并连接，无当前传输故障；不要求 Wi-Fi/SDIO |
| 控制通信 | UART0 命令接收已初始化、接收中断开启，无未处理的 UART 接收丢失 |
| 温度 | 最近一组 XADC、电源、AFE 三路均有效，采样年龄不超过 30 秒 |
| 配置 | 当前没有配置事务 |

正常停扫、关闭高压、停止上传或网络背压不单独表示故障；不用为了亮灯启动扫描、高压或 PC 接收程序。
AFE/TX 主动待机、过渡或故障均表示成像条件不齐全，因此熄灯。唤醒并通过全部检查后自动亮灯。
CPU1 是否被用户禁用、CPU0 是否启用可选 WFI，不影响这个灯；双芯片待机进入 WFI 前已经熄灯，不增加周期唤醒。
帧缓存淘汰/丢帧计数不属于故障；PL `FS_ERRORS` 非零保守保持熄灯，直到正常重新初始化清零，不自动执行复位。

PS 在前台每 100 ms 评估一次，仅 LED 电平变化时写 GPIO、故障掩码变化时打印；不增加 SPI 轮询或传感器读取。
SDIO 健康字及心跳复用现有 500 ms 统计同步，心跳连续 1.5 秒无推进即失效。
长时间阻塞前台时，软件指示更新会延迟；这不是独立硬件看门狗。亮灯不证明模拟回波、图像质量或高压实际电压正确，未发送图像时也无法证明 PC 接收端存在。

## 诊断

状态变化输出：`@HEALTH led=0 faults=04 ...`。`faults` 为十六进制按位组合：

| 位值 | 原因 |
|---|---|
| 01 | 启动/冷启动恢复未完成 |
| 02 | DDR 帧缓存不可用或报错 |
| 04 | AFE 接收链或最近 SPI 操作异常/未就绪 |
| 08 | TX 未就绪 |
| 10 | 当前选择的数据链路未就绪 |
| 20 | UART0 控制入口异常 |
| 40 | 温度读取失败或过期 |
| 80 | 正在配置 |

`led=1 faults=00` 表示本次检查全部通过。LED_2 原有运行闪烁逻辑不变。
规范源曾将 LED_1/LED_2 映射写反；本次按当前 Vitis 的实际配置同步为 LED_1=EMIO54、LED_2=EMIO55，不改 PL 引脚约束。

## 更新与验证

需要更新 **Zynq 应用 ELF 和 ESP32 固件**。未修改 PL、bit/XSA、FSBL 或 BOOT.BIN。
SDIO 协议仍为 v4，新增只读健康信息寄存器 58/59；旧 PS 可忽略它们，新 PS 搭配旧 ESP32 时会因缺少健康回报保持灯灭，但不会因这个指示功能主动禁止原有传输。

Zynq 使用 `workspace/B_mode_focus_imaging/build/B_mode_focus_imaging.elf`；标准输出同步到 `build/output/B_mode_focus_imaging.elf`。
ESP32 在工程目录执行 `./build.ps1 -Action flash -Port COM3`（端口自行确认），这里只提供命令，本次没有烧录。

离线验证包含每项故障熄灯、组合恢复、初始化、USB/SDIO 分支、限频、SPI 超时、温度失败/过期及 ESP32 心跳停滞；健康判定模块行/分支覆盖均为 100%。
回归与构建日志统一在 `esp32c61/logs/health_*_20261028.log`。实际灯极性、断网熄灯、冷启动恢复亮灯、两芯片待机/唤醒及图像吞吐需板上验收，本次未操作硬件。

本次结果：Python 回归 246 项（245 通过、1 项历史 TXT 缺失跳过），构建脚本回归 32 项通过，网页 43 项及图像页 5 项通过；Zynq USB/SDIO、当前 Vitis 应用及 ESP32 默认/combined 构建均通过。配套产物绝对路径和 SHA-256 记录在 `esp32c61/logs/health_artifacts_20261028.json`。
