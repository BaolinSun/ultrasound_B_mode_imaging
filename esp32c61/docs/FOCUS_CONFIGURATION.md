# 网页焦点配置

## 使用入口

控制台 → **高级参数配置 → 焦点配置**，或打开 `http://192.168.3.27/parameters`。

本功能使用 `esp32c61/configs/delay_profile_focus_20mm.json` 至 `delay_profile_focus_170mm.json`，共 16 张预先生成的完整延时表，每张 16384 个 32 位字。不会在网页重新计算焦点，也不依赖 PC Python 后端或 USB 控制台。

## 操作步骤

1. 在页面查询 PS 状态，确认 AFE、TX 就绪且没有其他配置操作。
2. 在焦点卡片中选择 **20～170 mm**，每档 10 mm。可以拖动竖向滑条、点击 `− / +`，或使用常用档位按钮。滑条向下为更深的焦点。
3. 检查“待设置焦点”和文件名。初始选中 **80 mm 仅为界面预选值**，不是对 PS 当前焦点的判断。
4. 点击 **停扫并应用焦点**，确认关闭高压、停止扫描、排空上传。
5. 等待完整表下发完成，页面和下方回执区会显示进度。不能将拖动选档、文件加载完成或部分 ACK 当成整表配置成功。
6. 成功后扫描、高压和上传仍保持停止。按实际需要回到控制台手动恢复扫描及高压，再在实时图像页开始接收。

下发依次执行 `CFG BEGIN`、2048 条 `BRAM WR delay_profile`、`CFG END`、`STATUS`。每条最多 8 个字，每批最多 8 条命令；仅写入延时表，不改变 `t_timing`、下采样、采样点数、显示深度、AFE 或其他配置。

“本页最近成功下发”是本页面收到完整 ACK 和最终停机状态确认后的历史记录，不是 BRAM 回读或声场焦点测量。重新打开页面时不猜测硬件当前焦点；其他入口改写延时表后，该历史记录也不能证明其仍在使用。

## 草稿、失败与取消

- **载入延时表草稿**：读取所选内置表，放入“参数编辑 → 发射延时”，保留其他类别草稿，不发送参数。可通过后续“校验并预览命令”“应用选中参数”编辑下发。
- **停扫并应用焦点**：始终使用所选的内置原表，不使用手工修改后的草稿。两种入口不要混淆。
- 内置文件长度和 CRC 在浏览器验证通过后，才允许进入配置事务；文件读取、校验或准入失败时不发送写命令。
- 取消当前操作或使用安全停止可以终止后续下发，但已经写入的字不会回滚。失败或结果未知后不要自动恢复成像；先查询 PS 状态，确认事务已结束，再显式重新应用一张完整正确的表。
- 配置期间保持页面在前台，不要关闭页面或让手机锁屏。文件加载有截止时间，传输批次复用现有任务超时与失联清理机制，不自动重放命令。
- 焦点不写入 NVS。Zynq 重启后以其 C 数组初始化值为准，而非网页最近选择值。

## 当前源文件中的重复表

提供的延时表中 **60 mm 与 70 mm、100 mm 与 110 mm 的所有传输字分别相同**。网页会提示这种情况，并保持原数据下发，不擅自修改或插值。同一张延时表不能仅凭文件名证明不同的实际焦点；请核对原始生成参数及实际成像效果。

## 更新与资源

本次仅修改 ESP32 网页、静态资源服务及构建工具。现有 PS 已支持 `BRAM WR delay_profile`，**无需更新 Zynq ELF、bit/XSA、FSBL 或 BOOT.BIN**。

在 `esp32c61` 目录执行（端口按实际连接修改）：

```powershell
.\build.ps1 -Action flash -Port COM3
```

完成后用 `Ctrl+F5` 刷新高级参数页。更新是用户主动执行的步骤，本次离线实施没有烧录或操作板卡。

修改/替换 `configs` 中的源文件后，需重新构建并更新 ESP32，页面“重新读取目录”只读取当前固件，不能读取 PC 磁盘上的新文件。构建会验证所有 16 档，缺失或错误时拒绝生成资源；这些源文件已作为构建输入纳入 Git，运行日志仍保持忽略。

16 张表的压缩包合计 **176521 字节**，直接从 Flash 提供，ESP32 不展开整表、不增加整表 JSON 堆分配。浏览器解压并校验后，仍按现有有界命令接口分批下发。此设计没有修复既有 `ESP-HTTP-001` 通用状态 JSON/SRAM 紧张问题。

选择焦点会改变发射/延时配置，区别于 PC 图像页仅调整观察范围的“显示深度”。实际焦点、成像效果和连续运行稳定性仍需上板验证。
