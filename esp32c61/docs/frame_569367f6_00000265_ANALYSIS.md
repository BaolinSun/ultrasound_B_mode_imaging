# 正常扫描抓帧离线分析：frame_569367f6_00000265

分析日期：2026-10-20。只读取用户提供的 TXT，不操作板卡，不修改采集文件、固件或参考工程。

## 结论

当前完整帧解析器验证通过：64 条逻辑线依次为 0～63，每线 8 字描述符加 6144 点，无抽取。没有发现缺线、重复线号、帧尾不足、行头错位或混合抽取。64 条线的载荷各不相同，时间戳持续递增，符合有时序推进的采集格式；但单份文件不能证明后续帧变化，也不能证明模拟接收/波束合成的数值或图像目标正确。

数据内容明显低码值量化：393216 个采样点只有 56 种值，零码占 42.3487%，没有 0xFFFF 饱和。所有数值逐项匹配当前默认 log_table_hex，反查地址范围为 0～56，约 98.9184% 的采样点对应地址 0～4。在默认 LUT 未被改写的前提下，这与对数前包络码偏低相符；不能据此单独认定是高压未开、增益配置错误、滤波截位、ADC 故障或 DDR 丢数。

## 时间戳

首线为 0x00113A20，末线为 0x00113C55；跨度 565 个 tick。63 个相邻差值中，61 个为 9、2 个为 8，无反向跳变。说明这份帧内的线时序连贯，没有明显长时间拼接断口；时间戳连续本身不是缓存所有权证明。

当前 `add_rf_head.sv` 每 3200 个输入时钟递增一次计数，`bproc_top.sv` 将该时钟连接到 clk_25。按其标称 25 MHz，tick 是 **128 µs，不是计数器名字 cnt_10us 所暗示的 10 µs**。首末线间隔名义上为 72.32 ms；仅可作为当前时钟连接下的估算，不能把它直接当作精确整帧周期、Wi-Fi 帧率或网络吞吐。整帧/网络帧率需要多帧编号和接收时序。
